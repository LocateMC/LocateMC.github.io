modsrc.dev 是 mcsrc.dev 的「模组版」：在 **Modrinth** 上挑一个模组与对应的 release，它就会在**你的浏览器里**下载该模组并完成反编译，随后即可像读普通工程一样翻阅它的 Java 源码。整个过程同样在本地进行——**模组文件与反编译结果都不会被上传到 modsrc**。

### 核心能力

- **直接在 Modrinth 里选**：从模组到具体 release 逐级选定，凡是 Modrinth 上架的模组都可以一试，不必回到 GitHub 找仓库。
- **浏览器内反编译**：沿用与 mcsrc 同一套方案（**Vineflower** 反编译器 + **`@run-slicer/vf`** 的 WebAssembly 封装），下载与反编译全部发生在客户端。
- **源码浏览体验**：完整继承 mcsrc 的编辑器与导航能力，读代码的顺手程度与在 IDE 里接近。
- **崩溃可续**：整体反编译一个体积较大的模组相当吃资源，站点会明确提示「可能把浏览器搞崩」；真崩了也不怕，重新打开页面即可从断点继续反编译剩余部分。

### 定位说明

站点自己标注了 **Proof of concept（概念验证）**，并提示功能、链接与行为都可能变化——换句话说，它现在处于「能跑、好用，但还在长」的阶段。它与 **mcsrc.dev 技术同源、界面同源**，可以理解成同一套浏览器内反编译方案在「原版源码」与「模组源码」两个方向上的两个入口。

### 社区生态位

它补上的是一个长期存在的缺口——「**模组源码的可读性**」：

1.  **不少模组只发布编译产物**：想弄清某个功能是怎么实现的，过去要么碰运气找到公开仓库，要么自己搭环境反编译，门槛不低。
2.  **省掉整条工具链**：把「找 jar、配 JDK、跑反编译、处理映射」压缩成「选模组 → 读代码」两步，读源码从一件需要专门安排的事，变成顺手一查。
3.  **与 mcsrc.dev 组成完整链路**：想理解模组对原版做了什么改动时，原版看 mcsrc、模组看 modsrc，两边对照着读，这套组合目前几乎没有替代品。
